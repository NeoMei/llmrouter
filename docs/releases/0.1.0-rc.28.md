# LLMRouter v0.1.0-rc.28

本次修复控制台的渠道连接测试，让 OCR 与图像模型能被真实探测，而不是被一律判为不支持。

PaddleOCR 渠道测试改为真实任务探针：提交一张 240×64 的文字测试图并轮询一次任务状态，提交成功且状态不为 failed 即判定连接可用。探针不写计费、不写请求日志、不推进多 key 轮换，也不占用用户的额度。图像类模型（qwen-image、dall-e、gpt-image、flux、seedream、kolors、imagen）自动改走图像端点。前端渠道行不再对 PaddleOCR 禁用测试按钮，只保留“获取模型”的禁用；客户端模型路由页的 OCR 说明同步更新。

同期完成阿里云渠道的命名与模型清单收敛：渠道改名为 Aliyun-Chat / Vision / Embedding / Rerank / ASR / Image / TTS / Video；Chat 24→20、Vision 3→1、Embedding 11→7，删除上游返回 model_not_found 的条目及其 abilities 行。该变更已直接写入生产库并保留回放 SQL，不经过控制台审计日志。

仍未覆盖：ASR、TTS、Video 渠道继续走通用 chat 探针，需要各自的请求形态（转写 multipart、异步视频任务）；qwen3-vl-embedding 只能用多模态 wire 验证。本次不改动计费规则、资金、账户与密钥。

This release fixes the console channel connection test so OCR and image models can be probed for real instead of being rejected as unsupported.

PaddleOCR now uses a real job probe: it submits one 240×64 text fixture and polls the job once, treating a successful submission that is not failed as a healthy connection. The probe writes no billing record, no request log, does not advance multi-key rotation and consumes no user quota. Image models (qwen-image, dall-e, gpt-image, flux, seedream, kolors, imagen) are routed to the image endpoint, and the channel row no longer disables the test button for PaddleOCR.

The same change set renames the Aliyun channels to Aliyun-Chat / Vision / Embedding / Rerank / ASR / Image / TTS / Video and trims their model lists (Chat 24→20, Vision 3→1, Embedding 11→7), dropping entries the upstream answers with model_not_found together with their abilities rows. That data change was applied to the production database with a replayable SQL script and does not pass through the console audit log.

Still uncovered: ASR, TTS and Video keep the generic chat probe and need their own request shapes (transcription multipart, asynchronous video jobs); qwen3-vl-embedding can only be validated over the multimodal wire. Billing rules, funds, accounts and credentials are unchanged.
