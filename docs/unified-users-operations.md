# UniHub 集成后的用户、管理员、预算和 Key

集成保留 llmrouter 的产品界面、路由、渠道、调用和监控。UniHub 管理统一身份、付费账户及统一调用的最终结算。

## 原有用户和管理员

部署同时开启 UniHub 和 `NATIVE_PUBLIC_ACCESS=true`，保留原有用户的兼容入口 `/sign-in?native=1`。原管理员仍使用原有 llmrouter 账号登录，用户、权限、余额、Key 和历史数据继续使用原有规则。默认产品入口使用 UniHub 登录。

原生账号与 UniHub 账号是独立身份，不根据相同用户名或邮箱自动关联。关闭兼容入口不会删除旧数据，但会阻断这些用户的公开访问；因此升级已有用户的实例应保留兼容入口，直到用户明确迁移。

## 统一用户与产品管理员

新用户在 UniHub 注册并登录，首次进入 llmrouter 时自动建立产品映射，无需第二次注册。产品默认成员权限由已注册的产品清单决定。

UniHub 用户管理员从统一用户管理界面选择用户、`llmrouter` 和目标实例，再分配 `product_admin` 等产品角色。角色变更在下一次权限验证时生效。`product_admin` 管理渠道、模型和产品运行设置；它不会使用户成为 UniHub 全局管理员。

UniHub 全局用户管理员通过部署配置 `USER_ADMIN_IDS` 指定经过核实的统一用户 ID。首次配置需在 UniHub 登录并确认本人 ID，然后由部署负责人配置；不能拿 llmrouter 原生用户编号或用户名替代。个人账户的 `owner` 身份不代表拥有平台管理权限。

## 预算、余额与 Key

统一用户打开 llmrouter 的 **API Keys**，先选择个人或团队付费账户，再选择资金类型与允许的模型，创建 Key。密钥只显示一次。Key 可以设置有效期、累计消费上限和单次上限，也可以撤销。

账户所有者或财务管理员可以调整该账户在当前产品实例的累计预算和单次限额。输入使用对应资产的常规单位，最多六位小数；留空表示不另设上限，零表示不允许新调用。预算不会增加余额。余额不足时通过 UniHub 的钱包充值、产品钱包划转或模型额度购买流程补充资金。

统一 Key 使用当前 llmrouter 的 `/v1` API 地址，可直接用于标准客户端。服务端补充调用编号和结算所需的内部任务标识；提供明确的 `Idempotency-Key` 可以防止同一逻辑调用重复发送。每次新调用重新校验用户、产品权限、付费成员关系、模型范围及预算。

## 查询调用和费用

llmrouter 的概览、模型分析、流量和日志展示真实调用与可信用量，并关联统一 Key。统一调用的金额及账户账单在 UniHub 查询；原生配额为零不代表统一调用免费。技术管理员的日志权限不会自动授予其他账户的财务权限。

升级不得自动迁移余额、修改旧 Key、合并身份或授予管理员角色。跨身份迁移需要明确目标、资源清单和单独确认。
