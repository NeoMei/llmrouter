# LLMRouter v0.1.0-rc.29

本次把渠道连接测试补齐到全部五类能力，并为真实异步与多模态请求提供各自的探针路径。所有连接测试均调用真实的上游收费 API，等待任务到达终态后才判定成功，不写计费与消费日志，也不推进多 key 轮换。

在 rc.28 的真实 PaddleOCR 任务探针与图像端点路由基础上，ASR、TTS、Video 三类不再走通用 chat 探针：语音转写走生产准入 `ValidateDomesticAudio` 与渠道自带 adaptor，以内联 WAV 载体提交；语音合成走 DashScope `multimodal-generation` wire（`{model, input:{text, voice}}`），以返回带签名的音频 URL 判定成功；视频提交真实 Wan 异步任务并轮询到终态。图生视频（i2v）由渠道 `settings.probe_seed_image` 提供真实首帧图，合成音色由 `settings.probe_voice` 提供；缺少首帧图时探针明确拒绝，不伪造图片。

同期修正若干供应商真实端点：qwen3-tts 不使用 OpenAI 兼容的 `/compatible-mode/v1/audio/speech`（返回 404），qwen3-asr-flash 走兼容 chat 的 `input_audio` 内联载体。渠道名保持供应商前缀 `Aliyun-*` 与厂商原模型 ID 不变；连接测试不产生 `logs type=2` 消费记录。生产渠道改名、模型清单收敛、首帧图静态发布等运行态数据不在本仓库内，按验收目录的回放脚本维护。

五类渠道（PaddleOCR、Image、ASR、TTS、Video）均已在生产控制台以真实调用实测：OCR 1.86s、图像 13.6s、ASR 372ms、TTS 1.01s、Video（wan2.6-i2v 真实首帧图）60.61s。本次不改动计费规则、资金、账户与密钥。

This release completes the console channel connection test for all five capability families, giving each real asynchronous or multimodal request its own probe path. Every connection test calls the real, billable upstream API and waits for the task to reach a terminal state before declaring success; it writes no billing or consumption log and does not advance multi-key rotation.

Building on rc.28's real PaddleOCR job probe and image-endpoint routing, ASR, TTS and Video no longer use the generic chat probe. Transcription goes through production admission (`ValidateDomesticAudio`) and the channel's own adaptor with an inline WAV carrier; speech synthesis uses the DashScope `multimodal-generation` wire (`{model, input:{text, voice}}`) and treats a signed audio URL as success; video submits a real asynchronous Wan task and polls it to completion. Image-to-video (i2v) takes a real first frame from the channel's `settings.probe_seed_image` and the synthesis voice from `settings.probe_voice`; without a first frame the probe refuses explicitly instead of fabricating an image.

Several real supplier endpoints are corrected: qwen3-tts does not use the OpenAI-compatible `/compatible-mode/v1/audio/speech` (it returns 404), and qwen3-asr-flash uses the inline `input_audio` carrier over compatible chat. Channel names keep the supplier prefix `Aliyun-*` and the vendor's original model IDs; connection tests produce no `logs type=2` consumption records. Runtime data such as production channel renaming, model-list trimming and static first-frame publishing lives outside this repository and is maintained through the replay scripts in the acceptance workspace.

All five channel families (PaddleOCR, Image, ASR, TTS, Video) were verified in the production console against real calls: OCR 1.86s, image 13.6s, ASR 372ms, TTS 1.01s, Video (wan2.6-i2v with a real first frame) 60.61s. Billing rules, funds, accounts and credentials are unchanged.
