# 国产模型账号池与资料库接口

本文记录当前分支的接口与运维边界。账号池核心、HTTP 请求切换、模型能力与文本向量契约、阿里兼容入口、PaddleOCR 公开接口与原生计费日志已通过独立审查。图片/音频/视频理解以及选定 ASR、TTS 路径也已通过独立审查；图片生成/编辑、多模态向量、管理界面和最终交付验收仍在实施；不能据此宣称这些待办已上线。

## 账号与公开模型

前端使用平台令牌、统一服务地址和公开模型名。供应商凭据继续保存在现有渠道/Gateway 密钥存储，健康记录不重复保存明文凭据。

- 原生多 Key 渠道的池为 `channel:<渠道ID>`。成员身份随凭据保持稳定，调整顺序不改变归属；替换秘密会形成新成员。
- Gateway 的池为 `gateway:<profileID>`。稳定的采购账号行持有任务归属，具体凭据版本持有健康状态。旧版本请求的迟到失败不会隔离更新后的凭据。
- 一个池应使用相同供应商、端点、认证形式与授权能力。普通 API 与 Coding Plan 若端点或权限不同，应建立不同池。
- 一个账号创建多个 Key 不代表多份容量。共享余额的成员可配置相同的管理员配额组；该组可跨池，但只能由管理员设置。
- 健康、手动暂停、凭据隔离和共享配额状态持久化于数据库。当前不依赖 Redis 保存池状态，选择和结果归因会增加短数据库事务。

原生渠道没有独立、可信的供应商账号标识，因此替换凭据后不能证明它属于旧账号。旧任务在这种情况下明确失败。Gateway 稳定账号行支持同一账号更新凭据后继续查询。

## 请求切换

轮询使用健康成员的最近选择顺序；随机模式保留随机候选。同一请求不重复发送给已尝试成员，优先尝试当前池的其他健康成员，再使用既有授权路由候选。每个实际发送共用 `RetryTimes + 1` 上限；设置为 0 时仍允许一次发送。仅跳过不可用池、尚未发送的候选扫描不消耗发送次数。

账号池请求不自动跟随 HTTP 重定向，防止 307/308 隐藏重复提交、绕过发送预算或上游禁止重试指令。应直接配置最终供应商端点。

- 普通 429 优先使用有效 `Retry-After`，缺省 60 秒，上限 10 分钟；到期重新具备选择资格。
- 已确认的余额/套餐拒绝使用结构化供应商证据。有可信重置时间时最多 32 天；没有重置时间时先冷却 1 小时。
- 已确认无效凭据隔离本次实际发送成员。通用 403、消息关键词和不明确的网络错误不会被当作全账号凭据失效。
- 成功不能清除较新的失败、手动暂停、凭据隔离或共享资金冷却。
- 全部不可用时返回真实错误及可计算的最早 `Retry-After`，不会在请求中等待数小时。

取消、上游 `X-Should-Retry:false`、余额不足、本地持久化失败或已输出响应后停止切换。流式连接中断后不承诺在另一个账号续接生成；已提交的保活输出也会触发保守的禁止切换。

图片/视频/任务创建、后台 Responses 等操作收到不明确的网络或 5xx 结果时不自动重提。明确的 401/429 拒绝可按原预算切换。平台只对最终成功结果结算一次；供应商已执行但响应丢失的额外供应商费用无法由网关消除。

## 资源与任务归属

新建异步任务保存实际成员的私有安全引用，查询、内容下载和 remix 沿用该账号，不能使用渠道的整个多 Key 字符串，也不能替换为另一个账号。

无法证明归属的供应商文件、加密内容、父 Response、条目引用和 Suno 续作引用在池模式下失败。现有作用域校验能够将本地 Responses 历史展开成完整普通消息时可以继续使用；不会放宽用户、令牌、路由、目标、渠道、客户端任务或模型边界。

池模式目前明确拒绝没有接入账号感知传输的 Xunfei WebSocket、实时 WebSocket、Midjourney/MidjourneyPlus 独立任务路径和 AWS Bedrock SDK 凭据模式。普通单 Key 旧路径保留；AWS API Key 的共享 HTTP 路径不属于该 SDK 限制。

BYOK 保持独立：存在但禁用/不可解密的 BYOK，或供应商拒绝 BYOK，均不能转用平台付费账号。

## 模型能力声明

路由的 `metadata` 仍是 JSON 字符串。新增字段均可省略；省略保持原行为，明确声明则在预扣和发送前执行约束。

```json
{
  "input_modalities": ["text"],
  "output_modalities": ["embedding"],
  "operations": ["embeddings.create"],
  "streaming": false,
  "async": false,
  "embedding_space": {
    "provider": "aliyun",
    "model": "text-embedding-v4",
    "version": "v4",
    "dimensions": 1024,
    "input_semantics": "text/query-document-v1"
  }
}
```

输入/输出模态包括 `text`、`image`、`audio`、`video`、`document`、`embedding`。操作使用能力清单中的完整名称，例如 `chat.completions.create`、`responses.create`、`embeddings.create`、`rerank.create`。能力注册不等于实际采购账号已开通。

`media_limits` 可声明 `max_request_bytes`、`max_images`、`max_audio_seconds`、`max_video_seconds`、`max_pages`、`max_pixels`、`formats`、`video_audio`。当前未获得可信媒体事实的时长、像素、页数、格式或音轨限制会保守拒绝相关输入/输出，不用 URL 后缀或客户端自报值冒充验证。后续媒体适配会补充这些事实。

明确能力路由仅允许直接、有限数值的采样标量覆盖：`temperature`、`top_p`、`seed`、`frequency_penalty`、`presence_penalty`。其他无法证明保留模型/媒体语义的参数覆盖被拒绝。未声明契约的旧路由保留既有覆盖行为。

Responses 的 `image_generation` 托管工具受图片输出与媒体限制约束；普通函数的名称、描述和参数结构保持不透明。`background:true` 属于异步请求，必须遵守 `async:false`，并使用异步创建的安全重试规则。

## 固定向量空间

相同维度不足以证明向量可混用。公开向量模型绑定供应商、实际模型、版本、维度和输入语义。每个目标的有效映射模型必须一致；目标可在自己的可选 `metadata` 中声明同一 `embedding_space`，不能覆盖成另一个空间。

在普通管理更新中，更改或移除固定空间需要不与原公开 ID/别名重叠的新名称。此保护不代替管理员主动删建配置或直接 SQL 的历史审计。

固定文本向量路径在发送前校验模型、维度和数值编码；在输出/结算前校验实际响应模型、批量数量、完整唯一索引、每条维度和有限数值。有效乱序结果按索引重排，保留原始数值与用量；错误结果明确失败并退款，不向客户端输出可入库结果。响应体最多 64 MiB。

版本与输入语义是管理员声明，不是代码对供应商不透明权重的证明。多模态向量应使用独立公共 ID，不能用相同 1024 维替换原文本索引。

## SuperWagie 资料库接口

已实现的受保护 POST 入口：

| 路径 | 契约 |
| --- | --- |
| `/v1/embeddings`、`/compatible-mode/v1/embeddings` | OpenAI 兼容文本向量，保留 `dimensions`、`encoding_format` |
| `/v1/chat/completions`、`/compatible-mode/v1/chat/completions` | 兼容聊天/已配置的视觉模型 |
| `/v1/rerank` | 规范重排结果 `results` |
| `/api/v1/services/rerank/text-rerank/text-rerank` | 阿里原生嵌套输入、`output.results` 输出 |

原生重排请求示例：

```json
{
  "model": "knowledge-rerank",
  "input": {"query": "问题", "documents": ["文档一", "文档二"]},
  "parameters": {"top_n": 2, "return_documents": false}
}
```

`top_n` 在 1 到文档数量之间；原始文档索引和排名顺序保留。Ali 两种入口都检查原始索引、有限分数、请求数量对应的结果数和明确非负用量，然后才输出/计费。畸形或超过 64 MiB 的结果失败并退款。

阿里原生重排入口需要适配器转换，因此当前拒绝请求体 passthrough。应为该路径关闭全局/渠道的请求体透传。语义参数覆盖也不能绕过原生请求校验。兼容聊天在已解析公开路由下只改写最终模型字段，保留其他原始 JSON 扩展和大整数。

现有 SuperWagie 索引绑定模型、地址和维度。即使仅从供应商直连地址改为 LLMRouter，也可能触发它的迁移保护。新库可配置网关；旧库必须由管理员显式验证并选择迁移/重建。本次实现不会修改、清空或重建真实 SuperWagie 资料库。

PaddleOCR 的内部任务、计费、结果存储和公开接口已接入。同步聊天 OCR 不能代替这套异步任务契约；最终整体和真实采购账号验收仍单独记录。

## 已验证的国产理解路径

当前有真实本地 HTTP 和计费回归的选定路径：

- Ali `qwen3.8-omni-flash`：直接、非流式 Chat/Responses，图片、音频和视频输入，文本输出。公开模型别名可以映射到实际模型。原始请求透传、自动跨协议转换、后台 Responses 和未验证的输出方式会在预扣前拒绝；这不是对所有 Omni 模型/账号的支持声明。
- Ali `qwen3.8-max`：兼容 Chat 的视觉/视频理解；文档支持的 `fps` 位于内容项顶层，范围 0.1–10。选定 Omni 没有已验证的客户端 `fps` 控制，因此拒绝该参数。DTO 能保留显式零值，不代表供应商接受零。

输入媒体事实只从有界内嵌 PNG/JPEG 和整数 PCM WAV 中验证：图片实际解码尺寸/格式，WAV 依据实际样本和块长度计算时长。最多解码 10 MiB 媒体字节、1600 万像素；未知压缩/浮点音频不冒充已有时长事实。选定 Omni 还检查文档要求的最小图片尺寸、宽高比与编码音频大小。URL 媒体不新增下载/探测；声明了必须验证的格式、像素、时长或无音轨限制时，无法证明就拒绝。不能使用 URL 后缀或客户端自报值通过校验。

音频语义请求保留供应商实际 text/audio/image/video/reasoning 用量。选定 Omni 按实际总量减去音频量，将其余输入/输出按已配置基础倍率、补全倍率结算；音频另用音频倍率。视觉余量在此路径没有独立的视觉价格，不能宣称已按另一套图像定价结算。推理和视觉余量只计一次，日志分别保留真实明细和计费基数。

选定模型的响应在向前端输出之前验证有界、非空的用量结构，必需总量字段不能缺失或为 null。明确存在且一致的零用量原样保留，不替换成估算值；按 Token 定价时真实零为零，配置的按次价格仍按请求单位收费。畸形用量不会输出可用答案，也不会换另一个账号重复生成。其他旧模型原有缺失用量回退行为保持兼容。

ASR 转写、TTS、图像生成/编辑及多模态向量是另外的操作契约，不能用上述理解路径替代它们的验收。ASR、TTS 的独立验收范围如下。

## 已验证的转写与语音合成路径

`POST /v1/audio/transcriptions` 支持 Ali 实际映射模型 `qwen3-asr-flash`，输入为有界 multipart 整数 PCM WAV，输出 `json` 或 `text`。总请求体和编码后的完整 Data URI 分别不超过 10 MiB，实际时长在 0–300 秒内。重复/未知字段、其他音频格式、翻译、时间戳和 verbose 输出在预扣前拒绝；不伪造片段或说话人。上游使用兼容 Chat 音频载体，公开别名映射到最终实际模型后再校验。实际文本/音频 Token 与 `usage.seconds` 必须存在且一致；日志保留实际秒数，秒数不转换成猜测 Token。

`POST /v1/audio/speech` 支持 MiniMax 实际模型 `speech-2.8-hd`、`speech-2.8-turbo`，使用原生 `/v1/t2a_v2`。非流式可选 MP3/WAV/FLAC/PCM；`stream_format:"audio"` 或 `stream:true` 提供二进制分块 MP3。流式不支持其他编码或对外 SSE。上游 SSE 经共享扫描器验证原生终态后完成，去除重复聚合尾包；二进制输出不会混入 SSE 保活或 JSON 错误后缀。已输出后失败会终止，不能跨账号续接。

请求不超过 128 KiB，文本为 1–9999 个 Unicode 字符。支持有界速度、音高、音量、情绪、归一化/LaTeX 与音频采样率等明确选项，保留显式零/false；任意 Metadata 不能替换已授权模型、文本、音色或计价语义。音频输出最多 32 MiB。原生 `usage_characters` 单独记录，Token 字段保持零；必须配置现有明确的按次价格（可显式免费），不能以文本 Token 比率猜测字符费用。正价格低于额度精度时预扣前拒绝。

首批只允许已核对的公共系统音色：`English_Graceful_Lady`、`English_Insightful_Speaker`、`English_radiant_girl`、`English_Persuasive_Man`、`Chinese (Mandarin)_Lyrical_Voice`、`Chinese (Mandarin)_HK_Flight_Attendant`。未知、自定义、克隆或生成音色缺少创建账号绑定，当前预扣前拒绝；不能依据名称前缀判断可跨账号使用。供应商实际账号的模型/音色授权仍需采购后验证。

精确原生错误码区分无效凭据、资金拒绝和操作限流，不能用错误消息关键词猜测套餐重置。未知执行结果不重复合成；明确拒绝可在共享预算内切换，已经输出则停止。取消、写失败、读超时关闭上游并等待扫描工作退出；失败交付沿用现有退款语义，供应商可能已执行的费用不由此消除。

当前本地测试用真实 PCM WAV 与可解码静音 MP3 验证协议、二进制字节和精确额度，不证明音质或供应商真实输出。MiniMax 官方响应元数据枚举对 WAV 的描述与请求编码列表存在不一致，WAV 实际原生响应需采购账号验收。原生限流后成功响应仍可能保留前一失败的 `Retry-After` 提示，已记录为非阻断修正项；实际成功音频和计费通过测试。

## OCR 持久化与结果边界

专用 PaddleOCR 渠道类型为 60，Gateway 保持 59。内部提交使用 v2 jobs 的 multipart 或 JSON URL 协议，并检查 HTTP 状态及 `code:0`。URL 文件会先受控下载、验证，再提供平台保存的输入地址；不把任意客户端 URL 直接交给供应商。支持 PDF、JPEG、PNG，最大 20 MiB、200 页；图片完整解码且不超过 2500 万像素。PDF 使用离线、有上下文和资源限制的解析器；这些是解析器每次分配等边界，不代表整个进程的内存/CPU 上限。

一个 OCR 任务只有一个持久化资金契约和一份预扣。必须配置明确的原生请求价格；不使用文本 Token 比率猜测文档价格。显式零价格可免费；正价格折算不足一个额度单位会拒绝。按现有钱包/订阅优先级预扣，供应商确认成功只结算一次，明确失败退款一次。下载或结果投递失败不把已执行的任务当成未执行退款。

只有明确的 401/429 拒绝可在同一渠道内切换成员，并共享持久化尝试上限。预扣后的跨渠道切换不支持，因为模型、分组、单价和渠道归因已冻结。提交超时、连接中断、5xx 或无法确认的响应保持执行不确定，不自动重提或退款。查询始终使用创建账号；Gateway 可刷新同一凭据行，原生 Key 被替换/删除则旧任务保守拒绝。轮询不会换成无关账号。

资金记录同时涉及 SQL 和 Redis 时，缺失回执或无法判定的效果进入待核对状态，不能根据缓存丢失直接重扣或重复退款。OCR 使用独立、关闭隐式重试的 Redis 客户端；不改变普通请求的全局缓存和批量记账机制。已有订阅重置、失效和删除的锁顺序保持兼容。

结果保留全部 JSONL 页序、表格、公式及原生扩展。只把图片 URL 值替换为平台资源引用，保留 Markdown 图片路径。JSONL 最大 32 MiB；图片最多 256 个，每个不超过 10 MiB，结果与图片合计不超过 64 MiB。输出页数必须与已验证输入相符，不能静默截页。

平台对象默认保留 7 天，下载授权按任务和资源限定。默认授权剩余有效期为 30–60 分钟；通过有权限的状态查询和 JSONL 投影续发，仍有效的旧授权继续有效。下载地址不包含采购 Key 或供应商任务 ID，数据库只保存授权摘要。图片只允许完整解码的 PNG/JPEG，响应需禁止 MIME 嗅探。创建/状态需要平台令牌；固定下游的 JSONL/图片下载只携带范围受限的下载授权。

SQL 与对象存储没有分布式事务。发布提交结果不明时保留对象，可能形成孤立对象；当前没有通用孤立对象扫描器。运行时会定期清理引用资源；首次结果交付的期限是任务创建后 7 天，发布后的资源另按发布时刻计算保留期。超过首次交付期限仍会恢复已确认执行的结算/失败退款，但不继续下载尚未保存的结果，查询返回 410。采购账号真实性能、供应商延迟取输入文件的行为和实际套餐定价尚未实测。

## OCR 公开接口与运行配置

| 路径 | 行为 |
| --- | --- |
| `POST /api/v2/ocr/jobs` | Paddle 原生兼容，HTTP 200，`code/msg/data`，返回平台任务 ID |
| `GET /api/v2/ocr/jobs/:id` | 同一用户和创建令牌查询，返回状态、实际进度及结果下载地址 |
| `POST /v1/ocr` | LLMRouter 异步扩展，HTTP 202，明确 `asynchronous:true` |
| `GET /v1/ocr/:id` | 状态和已就绪的实际页、Markdown、布局；保留原生扩展，无虚构坐标/置信度 |
| `GET /api/ocr/jobs/:id/resources/:resourceID?token=...` | 仅验证该任务/资源的有限下载授权，不要求平台 bearer |

创建接受一个 multipart `file`、`model`、可选 JSON `optionalPayload`，或 JSON 的 `model/fileUrl/optionalPayload`。不接受客户端指定渠道、供应商地址、分组或采购认证。未知/重复字段拒绝。`Idempotency-Key` 可选；提供时按同一拥有者和冻结契约复用，不提供则每次有意创建都是独立任务，不按内容偷偷去重。请求重试上限与 `X-Should-Retry:false` 保持一致。

HTTP 总请求体上限为 20 MiB + 64 KiB，且声明的 `max_request_bytes` 同时约束完整实体请求体（包括 multipart/JSON 包装、选项和尾随内容）。未知 Content-Length 的分块请求也按实际读取字节校验；媒体本身另受实际解码后的字节、格式、页数和像素约束。超限在创建资金记录、账号选择和上游发送前返回 400。

公开模型路由使用 `paddleocr_jobs` wire。固定 SDK 完整流程需要 `ocr.jobs.create` 和 `ocr.jobs.retrieve`；配置 `async:true`，不标成通用聊天。渠道 60 使用受信任的 BaseURL 和多 Key；Gateway 的原生 OCR 分支要求已配置、唯一有效的 `paddleocr_jobs` bearer profile。预扣之前选择有权限且健康的目标，预扣后仅在该冻结渠道内切换成员。

创建和查询均重新校验当前用户、令牌、模型、分组、渠道和冻结目标。创建刚好耗完令牌额度后，仍允许已启用/额度耗尽且未过期的创建令牌只读查询；新的创建继续按额度拒绝。禁用、删除、过期、IP/Origin 不符或其他令牌仍不能读取任务。查询不会因公开别名被重新路由就改用另一个供应商账号。

运行时配置：

```dotenv
OCR_PUBLIC_ORIGIN=https://llmrouter.example.com
OCR_GRANT_SECRET=<独立且持久保存的至少32字节服务端密钥>
```

下载域名来自受信任的配置，不能来自客户端 Host。两项均未配置时，其他网关功能可启动，OCR 返回未配置；显式配置不完整或非法时启动失败。沿用 `OBJECT_STORE_*`；多实例必须使用可共享的持久对象存储，以及相同的授权密钥。不要使用每次启动随机变化的密钥。

后台按有界批次恢复已接受的任务和明确终态资金决定，不重新提交执行不明的任务。每批最多 32 个任务、总计 3 分钟，每任务最多 2 分钟；资源清理另有 30 秒截止。关闭时取消并等待退出，再关闭独立 Redis 客户端和数据库。这些是运行边界，不是供应商完成时限承诺。

## OCR 消费日志

成功请求在现有消费日志中显示实际原生请求价格和额度，文本 Token 数保持零；`billing_unit=request`、`request_count`、原价格/分组倍率/资金来源等为安全元数据。失败、取消和预扣拒绝显示净额度为零的错误记录，不伪装成成功消费或再次退款。

主库的 `OCRAuditEvent` 是审计权威。SQLite/MySQL/PostgreSQL 日志库用同一事务写入 `Log` 和按事件 ID 去重的 `ocr_log_receipts`，因此日志已经提交、主库确认丢失后再次投递不会生成第二条记录，也不重做余额或计数。日志失败时事件待投递；后台独立投递，不改变任务结果。普通日志保留/删除时必须保留去重回执，备份恢复也需协调。

关闭 `LogConsumeEnabled` 会保留待投递的成功事件，错误事件仍可投递；重新启用后投递原始价格/时间，不重新扣费。主库与日志库没有分布式事务，保证依赖持久回执仍存在。独立 ClickHouse 日志库当前不支持这套 OCR 事务去重投递：保留主库审计并输出明确诊断，其他既有 ClickHouse 日志行为保持原样。此投递不另行仿造分析看板的计数副作用。

## 验证范围

当前证据包含 SQLite、MySQL 5.7.44、PostgreSQL 9.6 的池状态/并发回归；实际中间件、控制器、供应商适配器与本地 HTTP 服务的失败切换、授权、账本、退款和任务归属回归；受影响包的 race 检查及逐项独立审查。

这些是本地协议/持久化验证，尚未进行真实采购账号、生产 SuperWagie、部署或前端管理验收。OCR 的最小三数据库迁移/并发、公开真实鉴权 HTTP、创建归属、结果续期、重启与终态拒绝退款恢复、原生日志去重、完整请求体限制已通过针对性验证。最终全后端/前端、实际固定知识后端消费者与其余媒体端到端证据将在交付时更新。
