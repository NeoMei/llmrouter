# LLMRouter v0.1.0-rc.35

本次升级为 DeepSeek 补齐 Responses 原生搜索/抓取和独立 Search/Fetch 调用，并把计费绑定到实际上完成的工具调用。

- DeepSeek Responses 使用厂商原生 `/responses`；`web_search_call` 按终态 `completed` 项计费，`open_page` 计为 Fetch，其余动作计为 Search，失败调用不收费。终态响应中的工具项会覆盖流式暂存计数。
- 新增独立 `POST /v1/tools/search` 与 `POST /v1/tools/fetch`，只向允许两类操作的 DeepSeek 渠道转发原始 JSON。Search 仅在成功响应含非空 `results` 时收费，Fetch 仅在含非空 `content` 时收费；空结果释放预扣。
- 修正原先按工具声明、而非实际调用计费的问题。搜索与抓取默认价格均为每千次 0.75 美元。
- DeepSeek 模型目录更新为 `deepseek-flash` 和 `deepseek-v4-pro`，上下文上限为 1M。模型 token 价格采用统一的平日牌价，不根据工作时段或节假日切换：Flash 输入 2 元、缓存命中 0.04 元、输出 8 元/百万 token；Pro 输入 9 元、缓存命中 0.30 元、输出 27 元/百万 token。

DeepSeek Chat 的 `deepseek_web_search`、`deepseek_read_url` 与 `server_tool_calls` 暂不支持。它们需要 Chat 请求声明、流式调用记录、历史原样回传和独立用量计费闭环，当前没有可移植的上游实现；普通字段透传会丢失历史并产生未结算的付费调用。SuperWagie 的 `uh_model_` 托管路径仍拒绝内置工具，需另行确定搜索/抓取的冻结额度和结算契约。

This release adds native DeepSeek Responses search/fetch and standalone Search/Fetch forwarding. Only completed calls are billed; empty results release the reservation. DeepSeek model pricing uses the flat standard list price. Chat-specific server tools remain unsupported because forwarding their fields alone would break history replay and billing. The SuperWagie managed-key path also keeps rejecting hosted tools until separate reservation and settlement terms exist.
