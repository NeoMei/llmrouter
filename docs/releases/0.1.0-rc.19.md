# 0.1.0-rc.19 — Linux amd64 server preview

- Technical usage now distinguishes confirmed zero tokens, unavailable or invalid evidence, native measurement dimensions and centrally owned financial details. Legacy per-request evidence is checked against the frozen tariff instead of displaying a misleading local zero charge.
- Valid knowledge-provider usage that exceeds the existing reservation is retained as bounded, immutable, nonchargeable evidence. The result remains rejected and unresolved; this does not settle a charge, increase a reservation or retry a provider request.
- Capture and fault-waiver decisions recheck current immutable bindings and observations under database row locks. A retained overage cannot be mistaken for absent provider work or waived by the existing empty-evidence contract.
- Default frontend tests include TSX cases, and the browser fixtures and cross-database native usage setup match the current supported interfaces.

This release adds `platform_knowledge_rejected_usage` through the existing
knowledge-vault migration path. The deployment permits only this table and its
primary key as an additive schema change, preserving all existing tables and
business records. Keep the new evidence on rollback; never restore an old
database over new calls or balances. Any new rejected evidence or other business
changes require forward recovery review before an older binary can be considered.

The audited implementation is `4c6a5ee5d8dfa8b8c53ef151bdc1c8d29edde0e3`.
The release metadata commit changes only VERSION and this note. Existing
credentials, native product flows, identity modes, funding contracts, prices,
merchant settings and provider limits remain unchanged. Preserve the existing
read-only finance gate and leave the full finance gate unset. Deploy the matching

Controlled local acceptance includes 278 default frontend tests, 100 configured
browser cases, and selected PostgreSQL/MySQL/Redis regression contracts. The
source-bound evidence records carried unchanged domains separately from fresh
executions. Hosted CI, candidate build, migration rehearsal, deployed/public
readback and GitHub asset verification are separate release receipts.

This is a Linux amd64 server preview. Formal native plans, approved CREDIT
pricing, real merchant payment integration, all model purposes, multi-document
rerank and supplier accounting upper bounds remain unaccepted. It does not claim
desktop installation, signing/notarization or GA certification. No real model,
payment or balance operation is part of this release verification.
