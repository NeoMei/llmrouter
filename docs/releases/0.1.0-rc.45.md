# LLMRouter v0.1.0-rc.45

本版修复流式 chat 工具调用中 tool_call 字段被重复拼接的问题。上游在每个
tool_call delta 里重复下发完整 id / type / name 时，网关此前用字符串累加，
把 "function" 拼成 "functionfunction..."，在 completeCall 被拒并映射为
upstream_tool_protocol_invalid（502），而同一请求非流式正常。

relay/toolpolicy/stream.go 的 acceptChatFrame 现在以稳定字段语义合并
id / name / type：重复的完整值幂等保留，分片 id / name 仍能拼回，冲突的
type（例如 function 后跟 custom）直接拒绝；只有 function.arguments 继续按
分片累加。影响面覆盖所有复用 OaiStreamHandler 的 OpenAI 兼容 chat 渠道；
是否触发取决于上游是否在多个 delta 里重复完整 type。

包含回归测试：重复完整字段、重复 type 加分片 id/name、冲突 type 拒绝；
原有分片累加测试保留。go test ./relay/...、go test ./controller、
go build ./...、go vet 与 gofmt 均通过。
