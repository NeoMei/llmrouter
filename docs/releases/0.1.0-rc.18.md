# 0.1.0-rc.18 — Linux amd64 server preview

- Normal UniHub product-broker sessions can resolve the verified funding account and managed-model wallet, restoring the unified-wallet recharge handoff. Existing OIDC sessions remain supported.
- A separate `UNIHUB_PRODUCT_FINANCE_READ_ONLY_ENABLED` switch permits only the existing actor-bound GET allowlist. It defaults off, requires the existing runtime integration, and keeps broker finance POST/PUT/DELETE closed unless the original full finance gate is separately enabled. Read-only access reports empty write scopes.
- Wallet refresh preserves access only while the login method and bound identity stay stable. Revoked sessions, missing account authority, failed reads and late responses cannot show stale payer links or fabricated zero balances.

For this rollout, set only `UNIHUB_PRODUCT_FINANCE_READ_ONLY_ENABLED=true`
and the new VERSION; keep `UNIHUB_PRODUCT_FINANCE_ENABLED` unset. Do not
add central finance write permissions. All existing actor, session, subject,
product, instance and account-role checks remain enforced. The existing OIDC
user-bearer lane retains its prior authorization behavior.

This release changes no database schema, funding contracts, prices, model limits,
credentials or dependencies. It does not create or enable native subscription
plans, transfer balances, create recharges or settle payments. Unified cash and
llmrouter product cash remain separate balances. Opening the wallet and following
the recharge handoff do not execute a financial write.

Focused backend regression tests, 19 desktop and 19 narrow-screen wallet cases,
TypeScript, formatting, lint and the production web build passed locally. The
fixtures cover the actual default broker login method, read-only route boundaries,
valid Origin/CSRF write denial, revoked sessions, wrong accounts and login-method
changes during refresh. Exact-source hosted CI, image provenance and deployment
readback are separate release receipts; local tests are not production acceptance.

This is a Linux amd64 server preview. It does not claim desktop installation,
signing/notarization, GA certification, real payments, all model purposes,
multi-document rerank or provider accounting upper-bound acceptance.
