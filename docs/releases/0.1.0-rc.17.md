# 0.1.0-rc.17 — Linux amd64 server preview

- Native cash wallets show the authoritative unified CNY balance separately from the same account's managed llmrouter product wallet. The read-only cash DTO now carries the validated runtime funding account ID.
- Eligible UniHub OIDC sessions can read the bound account's managed-model cash through the existing user-authorized BFF. Missing authority, failed reads, account changes and late responses cannot produce fabricated zeroes or guessed recharge destinations. Normal same-session token refresh preserves access.
- Native recharge and insufficient subscription balance link to the verified UniHub account's explicit unified-wallet destination. Managed model cash links retain their separate product target. Cash mode hides unavailable legacy international payment controls while preserving configured WeChat and legacy local flows. English and Chinese desktop/mobile copy distinguishes wallet purposes.

This release includes a reviewed read-only Go DTO/projection change and frontend
changes. Database schema, financial write paths, funding contracts, pricing,
credentials, dependencies and production configuration are unchanged. The 300 CNY
product-wallet balance is not converted, transferred or counted as native unified
cash. Opening or refreshing the wallet performs no financial write. Deployment
changes only the image, VERSION and approved source labels, preserving existing
identities, API keys, balances, call history and ledgers.

Deploy UniHub's explicit `wallet=unified` deep-link support before this release.
Central recharge and sandbox settlement remain explicit user actions in UniHub;
this change does not enable additional service finance permissions.

The reviewed implementation passed focused Go cash/controller regressions, the
complete web verification pipeline (242 tests, formatting, copyright, lint,
TypeScript, production builds and Knip), 36 existing settings browser regressions,
and 12 new desktop plus 12 narrow browser cases. The fixtures cover 0 unified /
300 product cash, account permissions, 401/403, unsafe origins, subscription
handoff and token/identity races. They do not represent production financial
acceptance; final exact-commit hosted CI and release receipts are recorded with
the published artifact manifest.

This is a Linux amd64 server preview. It does not claim desktop installation,
signing/notarization, GA certification, real payments, all model purposes,
multi-document rerank or provider accounting upper-bound acceptance. Extended
copy outside English and Chinese uses the existing localization fallbacks.
