# 非破坏式统一用户修复验收

日期：2026-10-28。范围：本地 UniHub 与 LLMRouter 源码、真实隔离数据库及受控供应商。此报告不证明生产服务器已更新。

## 业务链路

UniHub 的 `TestManagedAPIKeyActualStandardGatewayAcceptance` 编译并启动实际 LLMRouter 路由测试进程，使用真实 PostgreSQL/Formance 与实际 HTTP、供应商适配器、会话签发及监控路由。OIDC 验签器与供应商响应是受控夹具。

- 通过中心 API 创建长期 Key，使用标准 `/v1/models` 和 `/v1/chat/completions` 完成普通、流式调用，不要求客户端额外提供内部任务头。
- 两个逻辑调用各结算 55 个 CNY/6 测试单位，总计 110；预算 `used=110`、`held=0`，对应钱包实扣一致。其他产品钱包、统一钱包保持独立。
- 中心结算后丢失响应，再重启 LLMRouter，恢复只重放结算，不重发供应商请求。相同显式幂等键返回 409；并发重复请求只允许一次发送。
- 使用实际签发的产品 JWT 读取原 `/api/log/self`、`/api/data/self` 和 `/api/data/flow/self`，查得同两次调用、30 个可信 token，本地额度消费仍为零。
- 原生标记用户的余额/已用/请求数及原生 Key 的余额/已用，在调用与重启前后不变。原生兼容路由另外验证原登录、刷新、JWT/PAT、Key、钱包记录及管理员鉴权。
- Key 撤销、到期、产品权限撤销、成员关系失效、错误模型/实例和预算不足均在供应商发送前拒绝。撤销或过期 Key 不能读取公开任务、结果或 receipt。

## 前端和权限

前端协议及交互覆盖统一登录、原生 OAuth 回调、应用导航、Key 创建/撤销、精确金额、预算版本、付费账户切换、密钥清除、财务数据隐藏、结算入口、注册失败恢复与权限撤销。直接 GET/HEAD `/keys` 及 SSO 回跳在原生隔离和共存两种模式均可用；原生 Key API 在隔离模式仍受限。

技术日志不包含凭据、供应商请求正文或未经授权的账户金额。消费日志关闭时，监控回填不阻塞其他审计事件。原生用量投影按事件唯一标识去重，不产生第二次扣费或第二份消费日志。

## 检查与边界

- 前端：171 项单元测试、49 项受控浏览器回归、类型、lint（仅警告）、格式、版权、knip 和生产构建。
- 后端：项目 `scripts/verify-backend.sh` 执行全包测试、vet、race、编译和 onboarding 检查；中心使用真实隔离 PostgreSQL/Formance 全包测试，并运行实际跨仓链路。
- 回归发现并修正：结束秒内调用遗漏、原生财务汇总越权、消费日志关闭时回填阻塞、可复用 Gin 上下文被数据库后台保留、测试退出前异步性能任务未排空。
- 独立审查覆盖中心凭证/预算、路由/原生兼容、监控、前端和各修复差异。

用户选择保留现有内部服务凭据，先完成代码修复。本阶段不修改服务器、产品客户端 registry、生产角色、余额或 Key，不发布版本。现网仍为此前部署；实际 Casdoor 浏览器登录、生产用户、付费供应商、真实支付及上线回读需要各自的证据。
