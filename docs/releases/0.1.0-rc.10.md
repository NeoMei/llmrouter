# LLMRouter 0.1.0-rc.10

修复 UniHub 集成对原有账户、API Key 和监控链路的破坏，保留统一身份与中心结算。

- `NATIVE_PUBLIC_ACCESS=true` 可以与 UniHub 同时启用，保留原有登录、用户管理、Key、额度、管理员和各协议调用。默认入口继续统一登录，原生入口为 `/sign-in?native=1`。
- 统一用户在同一个 `/keys` 页面选择付费账户、创建或撤销长期 Key、设置 Key 限额及账户预算；财务角色由中心在线校验。密钥只显示一次，切换账户清除旧数据与密钥。
- 统一 Key 支持标准 `/v1` 客户端，服务端补充内部调用标识和必要输出上限；显式幂等键防止重复发送。撤销、过期、模型/实例不符及额度不足均阻止新调用。
- 看板、流量、日志读取持久化统一调用与重试记录，按实际用户和 Key 归属展示可信用量。统一扣费与原生额度独立，技术日志权限不授予账户财务权限。
- 原生调用补齐幂等监控投影及可信 token 计数，历史成功事件可以安全回填；不重新扣费、不重复写日志。

原有账号、余额、密钥和历史数据不会自动合并或迁移。统一 Key 与预算需要配套 UniHub 0.4.10；产品 browser client 修改预算需要已登记的 `settings:write` scope 和账户所有者/财务管理员角色。

本地完整链路已使用真实 PostgreSQL/Formance、实际 LLMRouter 路由及会话、受控供应商验证普通与流式调用、重复调用拒绝、断响应重启恢复、一次结算、监控回读以及旧用户/Key 余额不变。浏览器交互测试独立覆盖 Key、账户切换与预算操作。实际 Casdoor 浏览器、生产用户、付费供应商和真实支付验收分别记录，不能由本地结果推定。
