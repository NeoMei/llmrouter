# LLMRouter v0.1.0-rc.43

本版收紧多模型统一 API Key 的能力边界声明，并修正计费在失败路径上把不确定资金结果写成确定结果的几类缺口。修正只涉及后端 Go 代码、文档与测试，不改前端产物、依赖或数据库 schema；新增的 wallet_refund_receipts 表由既有 AutoMigrate 与资金模型注册路径建表，不配独立迁移脚本。

## 统一 API Key 能力边界

- README 与 docs/unihub-platform-adapter.md 写明：统一 uh_key_ Key 的 /v1 分发是 router.SetManagedKeyDispatch 中显式的 method/path 白名单，白名单外的路径返回 HTTP 501 unified_operation_unsupported；Responses 在托管 Key 下强制无状态，有状态续接、provider-owned 文件/向量库/容器引用、后台任务与 Chat ⇄ Responses 自动格式转换均未实现。文档不把未验证能力写成已支持。
- relay/capability/defaults.go 收窄 responses.create 与 responses.compact 的能力注册到实际适配器与分发路径支持的渠道；新增 parity 契约测试，避免注册表与实现不一致。
- 新增 router/managed_key_whitelist_test.go 与 relay/channel/openai/responses_usage_wire_test.go，钉住白名单一览、代表性 501 错误码以及 Chat/Responses 两种 wire usage 拼写。

## 计费准确性

- 失败用量结算：HTTP 200 生成失败若携带供应商真实 usage，按一次结算并 skip_retry；estimated/missing 用量保持预扣挂起待对账；结算未落账返回 503，不再随后全额退款。FailedUsageConsumed 防止重试或重复错误路径二次结算。
- 耐久幂等退款：新增 WalletRefundReceipt，退款前同步建收据、额度变更与 applied 状态在同一事务提交，applied 收据幂等 no-op；恢复阶段逐腿补应用，全部腿完成后才关闭 lease；空 RequestId 时以 durable lease ID 或稳定派生值作幂等身份；即时与恢复路径在额度变更后失效用户缓存。
- 结算失败显式化：新增 BillingSettlementFailed、MarkReconciliationPending、IsSettled；SettleBilling 所有失败分支标记待对账，不再只写日志；非流式 200 已交付时阻止 JSON 覆盖与重试，预扣保持 pending。
- 缺失供应商用量：originUsage == nil 时不把估算 token、UsePrice 或 ModelPrice 反推为已验证用量；不确定预扣保持挂起、写显式 pending 审计、不写干净消费日志、不结算。
- Task 响应门控：pendingResponseGate 缓冲 Task 适配器的成功响应，只有结算与任务交接全部提交才返回 200；task.Insert 或 BindTaskTransaction 失败返回 503、阻止退款与 200 提交，避免留下会被二次退款或重新计价的轮询任务。
