# LLMRouter v0.1.0-rc.7

候选准备日期：2026-10-27。此服务端预发布候选修复 UniHub 注册被限流后的恢复交互。

## 更新内容

- 注册收到 `429 rate_limited` 时显示本地化等待提示，按 `Retry-After` 响应头或 `retry_after` 响应体进入冷却；冷却期间禁止提交，时间结束只允许用户手动重试，不自动注册。
- 首次请求只有收到 UniHub 明确的 `registration_not_started: true` 证明，才允许修改表单或返回登录；未修改时继续复用原始请求体和幂等键，修改后才开始新意图。
- 已有网络失败或 `UNKNOWN` 等未决注册时，即使后续收到限流及未开始标记，也继续保留原始请求，不解除未决状态。缺少标记的旧服务响应同样保持保守行为。
- 所有七种现有界面语言增加限流和未决请求提示。注册密码仅随组件内的原有请求意图保存，不增加持久化存储。

## 验证范围

`verify-web.sh` 已通过格式、版权头、lint、TypeScript、构建、158 项单元测试和 knip；新增五个注册限流 Playwright 场景均通过，覆盖初次恢复、编辑后新意图、原始重试、UNKNOWN/网络失败后限流及倒计时不自动提交。

完整 UniHub Playwright 29 项全部通过。同步纠正三项旧测试对原生登录或仪表盘地址的预期，显式以 `native_access: false` 验证公共 `/sign-in`、`/dashboard`、`/wallet` 路径保持 UniHub 边界、退出登录及身份不匹配拒绝；未改变生产路由策略。

本候选需配合 UniHub 服务端的未开始证明契约以恢复可编辑表单；旧服务端仍可得到友好的等待提示和原请求安全重试。本地模拟和构建不等同于部署或真实用户注册成功，部署后的只读检查及用户实际注册结果需单独确认。

本次范围为服务端预发布，不声明桌面安装、签名、公证、容器供应链或 GA 验收，不扩大真实支付或其他供应商验收范围。
