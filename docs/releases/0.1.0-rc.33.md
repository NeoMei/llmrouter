# LLMRouter v0.1.0-rc.33

按产品决定，把「空白页」从异常改成可交付结果：供应商确实执行了任务，空白页也是它交付的输出，因此正常归档并按成功结算。

具体规则：

- 页面没有 `markdown` 成员（供应商在这页什么都没识别出来）：视为空白页，正常归档、结算。
- `markdown.text` 存在但为空或全是空白：同样视为空白页，正常归档、结算。
- 有 `markdown` 却没有 `text` 成员、`markdown` 结构非法、`text` 类型不对：仍是契约违规，按原样拒绝，不归档也不结算。

rc.32 修的三处结构假设保持不变：官方结果桶分片主机（`paddleocr-store-2/-6`）、CREDIT 计价的 `llmrouter_native_credit` / `lr-native-credit-v1`、单 key 渠道绑定没有 `owner` 时以 `ref` 为准。

Product decision: a blank page is a delivered result. The supplier ran the job and charged for the request, so an empty page now preserves and settles like any other page. A page with no markdown member at all, an empty or whitespace-only text, both count as blank; a markdown member without a text member, malformed markdown or a wrong text type stays a contract violation and is still rejected without archiving or charging.

rc.32's three structural fixes are unchanged: the official result bucket's sharded hosts, CREDIT pricing sources, and single-key bindings that omit owner.
