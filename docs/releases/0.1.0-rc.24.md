# LLMRouter v0.1.0-rc.24

Bailian speech downloads can contain complete PCM audio with streaming placeholders in the WAV file's two length fields. These responses previously failed strict audio validation after the supplier had generated the audio and reported its character usage.

The Bailian adapter now normalizes only the observed placeholder pair in a canonical 24 kHz, mono PCM16 WAV. It requires a completely read, bounded HTTP body with an exact Content-Length and no transfer encoding, copies the audio before updating the two lengths, and retains the existing strict audio and duration validation. Other malformed WAV files, incomplete downloads, generic compatible audio and other providers do not receive this exception.

Supplier character usage, original account Key and payer, duplicate-request protection, and settlement-before-delivery behavior remain unchanged. Existing unresolved calls are not retried or automatically settled by this change.

Regression validation includes replaying the retained supplier WAV without another supplier request, incomplete and malformed downloads, immutable source bytes, generic and ElevenLabs rejection, and a managed speech call that settles the original supplier-reported characters before returning normalized audio. This prerelease requires no database schema or configuration migration.
