# 六类原生计量与实际结算设计

状态：用户已于 2026-10-26 确认，允许同时修改 LLMRouter 与 UniHub；尚未修改结算代码、迁移价格或部署。

## 目标与范围

实现用户指定的六类计费：对话与 embedding 按供应商实际 token；TTS 按字符；STT 按音频秒数；图片按成功张数和尺寸档位；OCR 本期按成功请求，后续可按成功页数；视频按供应商实际单位或成功输出秒数。

推荐同时覆盖 LLMRouter 原有本地资金路径和 UniHub 平台资金路径。两者共享计量证据与单位定义，各自使用原有资金权威：平台调用只由 UniHub 定价和入账，本地调用使用本地钱包／订阅。每个逻辑调用只能选择一个资金路径。

“支持一种计费方式”必须包括：后台配置、调用准入、可靠计量、预留、成功结算／失败释放、异常恢复、账单展示和验收。六类方式全部完成后才算交付；供应商适配覆盖需列清单，不能用猜测 usage 或隐藏估算补齐不支持的渠道。

## 方案选择

推荐“共享计量合同 + 各资金路径结算适配”：供应商适配器输出事实，定价器按冻结价目算费，资金层执行可恢复的结算。复用现有 token 表达式、OCR 操作回执和平台结算意图机制，针对实际缺口改造。

另外两种选择：逐个适配器追加倍率，首轮改动较小但难以处理零量、价格迁移及平台合同；重写全部资金账本，范围与迁移风险过大。推荐方案对外统一单位和行为，内部保留现有资金所有权。

## 统一计量合同

在不依赖 service/model 的公共包中定义版本化计量合同，供 relay、异步任务和平台适配器使用。避免继续往通用 token 字段塞字符、秒数和供应商扣费单位。

每份计量证据包含：

- 合同版本、operation、逻辑调用 ID、供应商请求／任务 ID、尝试 ID。
- `confirmed / missing / invalid / incomplete` 状态；请求估算另存，不能当最终证据。
- 一组有单位的计量项：数量、计数来源、测量规则版本、档位及完成输出标识。
- 数量为有界的规范十进制整数字符串加 scale；例如 `12345, scale=3` 表示 12.345 秒。供应商小数单位无损保存，不能先转整数或 float64。
- 缺失项与显式零值严格区分。已确认零量允许最终金额为零；非法负数、溢出、非有限数、重复或冲突字段不能进入结算。
- 首个已提交的最终计量版本固定；同一调用／输出 ID 后续出现不同数量、尺寸、单位或终态时进入冲突核对，不静默替换或重复扣退。已结算金额的修正使用独立、幂等且有授权的调整操作。
- 仅存必要用量和审计标识；原始提示词、音频、图片、密钥和带签名 URL 不进入财务证据。账单给用户展示单位／数量／单价／金额，管理员另看计量来源与异常。

统一结构区分基础单位与计价分母：`character` 是单位，“每千字符”是价格的分母；`audio_second` 是单位，“每分钟价格”通过 60 秒分母表达。

## 六类具体规则

| 类别 | 最终计量 | 预留依据 | 完成条件 |
|---|---|---|---|
| 对话、embedding | 上游原始响应的实际 token，保留 cache、reasoning 等原生语义 | 请求上下文和明确输出上限的保守界限 | 用量字段存在、合法且满足该协议的完整性规则；批量 embedding 的总用量只计一次 |
| TTS | 已声明规则下的实际字符数 | 最终发往上游的文本字符量和价格规则 | 供应商完成生成；优先使用经适配器验证的实际字符量，无该字段的模型使用明确声明的服务端文本计数规则 |
| STT | 经验证的输入音频实际时长 | 服务端验证的音频时长及模型限制 | 成功转写；使用可信供应商时长或经验证的服务端音频测量 |
| 图片 | 按档位汇总成功完成图片数 | 请求张数和允许的尺寸／质量档位；auto 使用有界的最高允许价格 | 完成图片，不包含预览／partial 事件；重复完成事件去重 |
| OCR | 一个成功终态任务计一请求 | 一请求固定价 | 供应商确认完成且成功证据通过契约校验；失败释放，重复轮询不多收 |
| 视频 | 该模型价目指定的供应商单位，或所有成功输出的秒数总和 | 有界的时长、数量、分辨率或供应商单位上限 | 供应商成功终态，实际单位／时长来自可信回执或受限媒体测量 |

### 对话与 embedding

在原始 JSON／SSE 边界采集证据，先确认字段存在性再进入通用 DTO 和协议转换。上游明确报告的 0 保持为 0，不能触发本地补估算。流中多次累计 usage 按各协议语义合并／替换，不能简单相加。

保留 `billingexpr v1` 的 token 变量语义与缓存规则，以已确认的原生 usage 为输入。无需把字符、秒数强塞进现有 p/c 表达式。Chat↔Responses、Claude／Gemini 转换应保持同一用量和费用。

### TTS 与 STT

字符计数策略是价目合同的一部分。建议提供 `provider_reported_v1` 和 `unicode_scalar_v1`：后者按最终发送的文本 Unicode scalar 数计算，空白、标点包含在内，不额外正规化文本。每个 model+operation 必须发布且只能发布一种策略；供应商字段缺失或矛盾时只能进入待核对，不能回退到 token 或未经声明的估算。Unicode 计数必须针对适配器改写后的最终文本。某模型固定采用哪一种必须明确；同一价格版本的路由候选需遵守同一规则。不得以模型名含不含 gpt 决定单位，也不得同时收字符费和供应商音频 token 费。

音频时长保留亚秒精度；按秒、按分钟仅影响价格展示。是否整秒进位和最小收费时长写入价目，默认按实际精度累计。客户端填写的 duration、文件后缀、未经校验的文件头不能直接作为收费事实。音频测量复用受限媒体读取与校验，施加格式、大小、时长和执行超时限制，并持久化媒体摘要和测量规则版本，避免临时 URL 或文件过期后无法复核。

TTS/STT 生成或处理结果已确认后，客户端接收失败不能自动等同供应商未执行。中断且无法确认最终用量则进入待核对。

### 图片与视频

尺寸档位按模型定义，可按宽高或像素区间配置，并把质量／分辨率作为明确维度；拒绝重叠或未覆盖的已启用档位。实际尺寸取可信输出元数据或受限媒体探测；只有供应商契约保证请求参数与输出一致的适配器才可使用该保证，`size=auto` 不直接沿用请求值。

图片请求 4 张、终态确认仅成功 2 张：收 2 张对应档位费用，退其余预留。只看见 2 张 completed 但连接中断、剩余状态未知：记录已确认产出及未决部分，整单等待最终确认，不能把预扣 4 张视为最终实际量，也不能自动全退。每个 confirmed output 先持久化证据摘要，最终计量完整后写入唯一的整单结算意图，再执行资金动作。明确零产出可以释放全部预留。

视频每个模型明确选择 `provider_unit` 或 `video_second`，缺一种数据时不临时改用另一种价格。provider unit 必须带命名空间与语义版本，防止不同供应商的“一个单位”混用。豆包实际 token 可作为一种明确的供应商单位；可灵单位保留小数。Sora/Ali 的现有时长字段需逐个验证其为实际产出而非请求回显；Veo 缺少可信字段时使用受限产出探测，无法测量则待核对。

供应商原始 token／成本可独立留作成本分析；用户单价由选定价目决定，不能同时按两种计量方式重复收费。

### OCR 本期与后续

本期保持成功任务按请求收费，并接入同一回执展示和 UniHub 资金路径。后续 `ocr_page` 作为独立价格版本启用，预留可用已验证输入页数，结算取可信成功页数；不能把输入页数或只解析出的进度字段直接冒充成功页数。

本期不开放按页收费开关，也不发布按页价格。页数规则、部分页失败和相应结算测试随后续版本一起交付。

## 定价、精度与兼容

新增显式单位价目，包含 operation、单位、计价分母、单价、资产、计量策略、档位、步长／进位规则、价格版本和生效状态。可在一个公共模型上为不同 operation 配不同价目，避免只按 model 字符串混用价格。

创建请求／任务时冻结价格、分组倍率、表达式、单位规则与所选档位约束。异步任务和重试不读取后来更新的价格。相同逻辑调用在重试时只能使用满足冻结计量合同的候选；资金来源、付款账户与资产不可变。

资金快照还需保存预留回执、订阅 ID、额度周期／ResetGeneration 和令牌预留 ID。跨订阅周期完成或退款时，只能按原周期预留规则解除／结算，不能给新周期凭空补额度。平台调用由 UniHub 原预留回执承担这一语义。

计算使用有理数或定点十进制：先汇总各计量项，再按资金系统规则做最终舍入。预留向上取整；本地最终额度走现有 `common.Quota*Checked` 并保留 clamp 审计，平台最终金额由 UniHub 精确计算。平台已有超过预留额记平台差额的政策保持由 UniHub 控制；不能在 LLMRouter 擅自改成透支扣款。

旧 `ModelPrice` 是固定单价，`ModelRatio` 是 token 倍率；不能就地重新解释为每字符／秒。旧规则标记为 legacy，迁移工具先生成逐模型新旧费用对照，再启用新版本。旧任务继续按原合同处理；缺少历史快照的任务明确进入历史对账，不能伪造旧价格。

## 结算生命周期与恢复

业务任务状态与计费状态分别保存。计费概念状态为：预留中、已预留、已派发、待计量核对、待结算、已结算、待释放、已释放。

1. 校验请求、模型计量能力、价格和数量上限，冻结合同。
2. 持久化逻辑调用，再确认资金预留；确认预留之前禁止发送供应商请求。
3. 派发前持久化 attempt，未知派发结果不得自动当成新请求重发。
4. 在供应商响应原始边界采集证据；异步任务成功终态和待结算意图在同一持久化事务中保存。
5. 幂等资金操作应用差额、释放余量并记录回执。零金额是有效结算，不能再用 `actualQuota <= 0` 表示“没有调整”。
6. 后台恢复未完成的资金意图，仅重试原结算／释放，不再次调用模型。财务恢复队列独立于“未完成生成任务”查询。

本地钱包／订阅／令牌的恢复不能仅靠外层重试普通增减函数：每个资金分量必须有稳定操作 ID 与持久回执，数据库和 Redis 按现有权威模式执行；不确定执行结果进入核对，防止重复扣退。复用 OCR 的 operations/receipts 思路，逐步接到新的计量结算路径，保留旧规则的兼容边界。

已确认执行失败且没有符合计价规则的成功产出时释放预留。HTTP 200 不代表生成成功；HTTP 错误、超时或客户端断开也不自动证明没有已计费用量。对话如果已有可信实际 token，按该 token 结算；按成功产出计价的媒体只计已确认成功产出。

缺失／矛盾用量进入可见的待核对状态，保留预留而不生成最终账单。后台仅在供应商支持查询时按原请求 ID 查证；否则进入人工核对队列。超时不能自动推断退款，人工调整必须带授权、理由与唯一操作 ID。用户可看到预留额与待核对状态，管理员可定位具体调用。

建议自动用量查证默认最多 20 次且不超过进入待核对后 24 小时，以先到者为准，按供应商限流退避；这是计量查证预算，不是视频生成任务的执行超时。超期转人工并告警。人工终结动作分为“确认实际量后结算”“确认未产出后释放”“平台承担损失主动释放”，记录授权人和理由；不能把承担损失伪记为供应商实际零量。这样既可审计，又有明确解除预留的操作入口。

本地钱包、订阅、令牌和 Redis 可能出现部分提交；只有所有资金分量的幂等回执都成功才可标记 `settled` 或 `released`。任一分量未知或失败都保持 `settlement_pending`，按固定 operation ID 恢复，禁止依赖单个余额字段或先写终态再补账。OCR 后续页模式也必须使用最终结果页数证据，不能把中途 `ExtractedPages` 进度直接作为收费页数。

## UniHub 协议扩展

与 UniHub 同步增加版本化计量价目和用量合同，例如 `metered_v2`，继续接受旧 `exclusive_v1`。新合同包含 operation、已发布的计量项与规则、严格数量／scale、档位和不可变价格 ID。只接受与冻结价目匹配的计量项，拒绝重复项、未知单位、错 operation 和资产混用。

LLMRouter 提交经验证的用量和证据摘要；UniHub 根据不可变价目计算最终金额、执行账本并返回回执。LLMRouter 的本地价格编辑器不能覆盖平台销售价格。CREDIT/6、CNY/6 保持独立，供应商成本继续为可选独立观测。

按 operation 扩展平台 routes/admission：Chat／Responses、embedding、speech、transcription、image generation/edit、OCR jobs、video jobs。异步创建、查询、取消、结果读取和计量恢复继承原 actor/account/origin/task 授权，不能依赖短期凭证一直有效；用户查询仍需当前有效的同域凭证。Multipart 请求先做有界校验和服务端测量，再预留；不能沿用只适用于 Chat JSON 的 body 限额规则。

当前原生 OCR service 固定本地资金 owner，需要拆出资金适配点后才能用于平台；平台请求不能先走本地 OCR 预扣再向 UniHub 收费。视频也必须在提交阶段固定资金权威并带入后台结算。

## 后台和账单

- 定价表单明确显示 token／千字符／秒／成功图片／成功请求／供应商单位，按 operation 展示可用单位与计量策略。
- 图片配置档位；音视频配置精度和计费步长；未知尺寸或未认证计量能力在启用前阻止发布。
- 价格预览给出实际数量示例及最终金额，迁移时显示旧、新规则差异。
- 账单展示实际数量、单位、档位、单价、价格版本、预留／实扣／退回以及待核对状态。原生字符／秒数不再显示成 token。
- 平台账单读 UniHub 回执，本地账单读本地回执。管理员计量证据不混入普通用户日志。
- 翻译按项目现行 i18n 约定补齐，金额和大整数用字符串处理，避免 JavaScript Number 损失精度。

## 验收矩阵

- 实际 token 与本地估算不同；明确全零、缺失、负数、溢出、重复字段、累计 SSE、缓存与 reasoning 分解、批量 embedding、协议转换费用一致。
- 中文／英文／空白／组合字符／emoji 的字符计数；供应商字符数与请求估算不同；同一 TTS 调用不叠加 token 费用。
- STT 0.1、1、1.001 秒；秒数与 token 同时存在；伪造时长、未知格式和超限拒绝；按步长取整只执行合同规定次数。
- 图片请求 4 张实际 2 张、明确 0 张、重复 completed、只有 partial、不同尺寸／auto、收到部分输出后断开；未知结果不冒充最终产出。
- 视频预留 10 秒实际 5 秒；实际超预留按各资金权威规则处理；多个视频时长求和；供应商小数单位无损；字段仅为请求回显时不能认证为实际量。
- OCR 重复 done、失败、未知提交、结果下载失败与重复查询；本期始终一成功请求只收一次。
- 预留后调价、跨渠道重试、跨模型／单位冲突、同幂等键不同正文、账户切换、重复回调、多实例竞争。
- 预留后订阅重置周期，再发生成功结算／失败释放；跨回调的冲突终态；待核对预算到期及三种人工终结动作。
- 在生成终态保存、结算意图保存、钱包／订阅／令牌更新、远端已应用但响应丢失、日志写入之间注入确定性故障；恢复后只扣一次、只退一次、回执一致。
- 本地 SQLite、MySQL、PostgreSQL 和配置的 Redis 模式；UniHub PostgreSQL／账本真实 HTTP 集成；CREDIT/6 和 CNY/6；平台调用本地余额不变。
- 前端类型检查、相关单元测试、lint、构建及配置／账单浏览器流程。供应商 fixture、真实资金服务、真实供应商请求分别记结果；没有真实调用证据的模型不标为生产已验收。

## 已确认的实施边界

1. 本次支持范围包含 LLMRouter 本地路径和 UniHub 平台路径，允许同步修改两个仓库的计量与价目协议。
2. 实际用量缺失／结果未知时保留预留并进入可见待核对；不自动用估算结账，也不把不确定执行一律退款。
3. OCR 本期仅按成功请求收费；按页作为后续价格版本，不在本期开放。

上线价格与生产切换仍需使用实际选定价目及完整验收结果。
