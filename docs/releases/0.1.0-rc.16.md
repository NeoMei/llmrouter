# 0.1.0-rc.16 — Linux amd64 server preview

- Wallet, statistics and order history distinguish loading, unavailable, stale values and authoritative zero. Invalid or incomplete success responses cannot become fabricated financial zeroes or empty history; safe retries refetch reads.
- Financial queries and native-key drafts follow the signed-in identity and funding realm. Existing LLMRouter product API keys retain their native ownership, payloads, quota controls and advanced settings.

The backend Go sources, API contracts, database schema, dependencies, credentials,
pricing, funding modes and model limits are unchanged. Runtime deployment changes
VERSION and approved source labels only. Existing identities, API keys, balances,
call history and ledgers are preserved in their native systems.

The reviewed source passed 35 focused desktop UI tests after the final response
validation fixes, TypeScript checks, production build and scoped lint (zero errors,
10 existing warnings). Earlier unchanged broader checks covered 8 mobile UI tests,
17 product-parity tests, 2 native-metering tests and 62 related node tests. These
are isolated UI/transport fixtures, not production financial acceptance.

This release is a Linux amd64 server preview. It does not claim desktop
installation, signing/notarization, GA certification, real payments, all model
purposes, multi-document rerank or provider accounting upper-bound acceptance.
French, Russian, Japanese and Vietnamese retain the disclosed English fallbacks
for extended technical explanations; full localization is not claimed.
